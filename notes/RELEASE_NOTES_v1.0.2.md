# TraeJumper v1.0.2 Release Notes

发布日期：2026-11-15

## 🎉 版本概述

**v1.0.2 — 应用内自动更新 + 续签稳定性修复**

本次迭代补齐了"应用自动更新"的完整闭环：应用启动后自动检查新版本、后台静默下载安装，并在完成后提示重启生效，不再依赖用户手动点击。同时修复了 OAuth 账号续签的优先级问题，完善崩溃捕获与日志诊断能力，并解决 Windows 平台频繁弹出终端窗口的问题。

**变更规模**：约 12 个源码/资源文件，+1099/-517 行（含 Cargo.lock 依赖同步）。

## ✨ 新功能

### 1. 应用内自动更新

v1.0.1 及更早版本只能在「关于」页手动点击"检查更新"。v1.0.2 新增后台自动更新：

- **自动检查**：应用启动 10 秒后检查一次，之后每 6 小时检查一次
- **后台静默下载**：发现新版本后自动下载并安装，不打断当前操作
- **进度提示**：页面顶部横幅实时显示下载百分比进度条
- **重启提示**：下载安装完成后横幅提示"立即重启"或"稍后"，重启后新版本生效
- 同一版本只处理一次；下载失败会自动清理横幅并在后续检查中重试
- 手动「关于」页检查更新保留，与自动更新共用同一套检查/下载/安装逻辑
- 开发模式（`npm run tauri dev`）下自动检查会跳过，避免误装正式包

### 2. 崩溃捕获与日志诊断增强

- 新增 Rust panic hook 与 Windows SEH 异常处理器，崩溃时输出可定位的日志
- 将阻塞式账号切换操作移至 `spawn_blocking`，避免阻塞 UI 线程
- 新增心跳线程与进程退出看门狗，便于排查无响应、静默退出等问题

### 3. 账号导出导入支持 OAuth 完整凭证链

账号导出/导入升级为携带完整 OAuth 凭证链（refresh_token、密钥对、device_id / machine_id 等），换机或重装后可完整恢复 OAuth 自管续签能力。

## 🔧 修复与改进

### 1. OAuth 账号续签优先级修复

- OAuth Native 与 OAuth 注入账号优先走 **ExchangeToken Refresh Flow**，不再误用 cookies 的 `GetUserToken` 导致客户端登录态互踢
- ExchangeToken 不作废旧 access_token，续签过程客户端无感，无需 kill + relaunch
- 无有效续签凭证时错误提示更明确：区分"缺少 OAuth refresh_token"与"缺少 cookies"

### 2. Windows 平台隐藏终端窗口

所有 7 处 `Command::new` 调用统一加上 `CREATE_NO_WINDOW`，切换账号、检测进程、启动 Trae 时不再闪现黑色控制台窗口。

### 3. Dashboard 标签文本微调

调整积分展示区域的标签文案，避免歧义。

## 📋 升级建议

- **1.0.1 用户**：可在「关于」页手动点击"检查更新"升级到 1.0.2；升级后后续版本将由应用自动检查并下载
- **全新安装**：直接下载对应平台安装包覆盖安装即可，数据格式向后兼容
- 自动更新在启动 10 秒后检查，之后每 6 小时一次；如需立即检查仍可前往「关于」页
- OAuth 账号续签现在优先使用 refresh_token，原有 cookies 续签方式继续保留给纯 Cookie 导入账号
